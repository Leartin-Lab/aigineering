## Objective and boundary

Produce reproducible measurements and same-fact differential evidence for (1) Asset-only signed Candidates and (2) mixed built-in Candidates containing an Asset plus a declaration. Attribute context loading, pre-commit Asset reduction, and writer-side Asset re-reduction as distinct stages. Measure the effect of closed unrelated history H, signed publication count P, and true relevant obligation/fanout/cascade size A. Keep same-batch declaration/Asset overlay and Asset-before/Contract-before order visible as correctness cases.

D0 does not change production code or implement locality. It excludes full task-board/readiness redesign, worker claim discovery, replacement-claim schema changes, general maintenance, provider execution, Redis, scheduler behavior and multiple DB backends. It cannot assert that SQL SUM, Redis, a benchmark fixture, or a read-only projection grants activation, claim, completion or acceptance.

## Fixture and matrix

Use the public CandidatePublisher / CandidateCommitter path, canonical built-in `contract.declare` and `asset.propose` effects, real Ed25519 identities and SQLiteStore. Never insert raw Contracts, Assets, traces or RuntimeRecords as a shortcut. Each cell gets an exclusive temporary Store, identity, output directory and pytest base directory. Prebuild history and report its cold-build duration separately from measured publication.

H is the number of unrelated Contracts whose signed normal lifecycle is closed, with their corresponding committed Assets and terminal facts. Verify terminal closure from Store facts before timing; no waiting or unclaimed root population counts as H. P is the exact number of accepted Asset publications in the measured cell: one Candidate holding P Assets for the batch cell, or P separately signed accepted Candidates against one continuously open Store for the sequential cell. A is measured from fixture facts and split into (i) activation/output Contracts hit by the changed names, (ii) same-name fanout, and (iii) descendant count/depth actually traversed on completion. Report these components and the number of refs per Contract; never equate A with P.

Full timing matrix, at least 3 independent samples per cell:

- Modes: `asset_batch` (P Asset effects in one Candidate) and `asset_sequential` (P one-Asset Candidates; no Store reopen between siblings).
- The sequential mode signs one Candidate per publication, with distinct Candidate IDs in order; the batch mode signs one Candidate containing P effects. A paired instrumentation twin reuses that mode's exact signed Candidate bytes/effect-payload sequence and history. The two modes are not required to share Candidate IDs with one another.
- P = 8, 16, 32, 64. H = 0, 16, 64. This is 12 cells per mode, 24 total cells, 72 timing samples. If cost is material, run smoke first and yield the full command rather than opening a duplicate. Do not reduce P/H after observing results without issuing a new plan revision.
- Fixed-A sparse scenario: a fixed small set of nonterminal Contracts has `activation=changed_signal` and a distinct declared output that none of this cell's P Assets provides. Publish P Assets with P distinct names and IDs; exactly one name is `changed_signal` and can activate the fixed Contracts, while the other P-1 names are explicitly nontriggering. The first Asset cannot satisfy the distinct output or close the Contracts, so A stays active through the sweep. These are measured publications, not unrelated H; H contains only separate, closed Contracts/Assets. Keep activation/output fanout and reference cardinality fixed as P grows. A separate completeness/qualification microcase tests output-triggered closure rather than mixing it into this sparse sweep. Assert P accepted publications/effects as applicable, `len(decision.assets)`, and unique Asset IDs; do not assume the requested P equals the observed accepted/unique counts.
- Instrumentation pairing is explicit: each of the 72 uninstrumented timing samples receives one instrumented twin using the identical source fixture and signed Candidate bytes within that mode (72 additional instrumentation runs; no instrumentation wall time enters the timing summary). The batch and sequential modes need not share Candidate IDs with each other. For each timing/twin pair, compare the exact accepted decisions and semantic fact identities. The six context-attribution inputs below (H=0/16/64 × asset-only/mixed) each receive one uninstrumented execution and one instrumented twin; these add six runs to each pass, for 78 timing and 78 instrumentation executions total, excluding smoke microcases. The microcases are covered by smoke correctness tests, not silently counted as matrix samples.
- Correctness microcases (smoke and instrumentation): Asset before Contract; Contract before Asset; same Candidate with both declaration and satisfying Asset (pending overlay/order independent); multi-name activation conjunction with one missing input; a separate duplicate-name case; completed parent with one unfinished descendant branch, one already-terminal intermediate with an unfinished grandchild, and a live independent-verifier branch. Record actual A and depth. The duplicate-name batch uses same-name/same-content effects and reports `decision.assets` effect count separately from unique Asset IDs; a sequential duplicate-name example uses distinct Candidate IDs and reports the resulting semantic IDs. Also include an independent-output Contract whose Asset exists but is not qualified, and an exactly qualified Asset to demonstrate that Asset presence alone is not acceptance.

For context attribution, run two explicit built-in candidate shapes at H=0/16/64: `asset_only` and `mixed_asset_declare`. Both are signed ordinary Candidates; the second carries one valid declaration plus one accepted Asset so the same-batch overlay is exercised. Instrument the calls to `load_contract_declaration_projection_context` and its fallback `load_effect_projection_context`, counting actual Contracts, Assets, records and claim-history IDs returned at each call. These are separate context-cost observations, not reducer-only counts. Pure `contract.declare` can be included only as a labeled C1 control; it must not be presented as an Asset Candidate. Exclude injected effects from this D0 context comparison: their writer snapshot re-projection is a separate path and should not be conflated with Asset reducer scans.

## Measurement and attribution

Follow B's report discipline: package/imported-file manifest digest, script digest, driver checkout revision, imported source label and exact archive digest, Python/SQLite/package versions, structured cell inputs, exit code/failure category, construction time, separate wall-time samples/median/p95, counters and no payloads, credentials, local store paths or raw exception text in any public-facing artifact. Output creation is exclusive; preserve nonzero results and stderr under private evidence. Use the absolute project `.venv/bin/python`, isolated basetemp, and a private output directory. No provider or Redis environment variables are needed; assert the measurement path does not instantiate either. Add explicit package-origin guarding: `--package-root` selects the directory containing the expected `aigineering` package (default the frozen script checkout’s `src`); set that import path before lazy runtime imports, reject already-imported modules from another root, and verify the actual imported package and complete module-byte manifest match it. CWD alone does not prove isolation because the project interpreter has an editable-install `.pth`. An installed-artifact verification bundle must supply its actual wheel install root explicitly.

Use paired passes over deterministic twin Stores built from the same signed history and Candidate bytes. Every P-matrix timing sample has exactly one instrumentation twin; there are 72 timing executions plus 72 instrumentation executions. Each of the six context-attribution inputs is likewise paired once (six uninstrumented semantic executions plus six instrumented observations), for 78 executions in each pass. No extra instrumentation-only P/H cells are implied.

1. **Timing pass:** no instrumentation hooks; measure total one-Asset / batch commit wall time only after history construction. Preserve all samples, including failures.
2. **Instrumentation pass:** a test-only observer (no production telemetry) wraps Store reads and pure reduction call sites, recording call count, number of returned/materialized Contracts, Assets, runtime rows and facts by stage: projection-context loader, pre-commit `reduce_asset_facts`, nested `writer_reduce_asset_facts` plus the inclusive `writer_ingress_consequences_total` wrapper. The paired instrumented twin must reproduce the same accepted/rejected decision and semantic facts as its timing twin. Construct the signed setup once per sample and take two private SQLite backup snapshots of that exact verified prefix before the timed/instrumented publication. Never borrow a prefix from a different cell or fabricate accepted history. Reuse the identical signed measured Candidate bytes on both twins. Differential digest compares canonical IDs and effective semantic fields; it excludes `RuntimeRecord.recorded_at` and `TraceEntry.timestamp`, which are display times, and must not claim equality by hashing those timestamps. All remaining IDs and semantic/causal fields must compare exactly; there is no ID normalization or renaming escape. A real time-bearing exception requires a separate plan audit naming the precise record type/path and bijective mapping before implementation. Count actual returned rows, not fixture-estimated H. Use SQLite trace for SELECT count and `EXPLAIN QUERY PLAN` for current relevant reads; progress-handler callbacks × declared interval are a VM-work proxy only (never an exact scan row count or bound). Record Python profile call counts separately; do not infer inner loops from SQL rows.

Use a test-side stage stack with distinct labels: `projection_context_total` contains `full_projection_context` on fallback; `pre_commit_reduce_asset_facts` is the pure pre-commit reduction; `writer_ingress_consequences_total` contains `writer_reduce_asset_facts`. The ingress helper also performs trace deduplication and terminal allowance work outside that reducer. Report parent-inclusive and leaf/exclusive metrics explicitly; inclusive parent and child values must never be added as separate work. Assign each observed read once to its current exclusive stage, retain a top-level publication total, and label remaining commit work `other_commit_work`. Smoke checks prove nested totals/exclusive attribution cohere; do not label the whole ingress helper as FactReducer or double-count the fallback loader.

Capture context-loader counts independently. An Asset-only Candidate currently enters `load_contract_declaration_projection_context` and falls back to the full `load_effect_projection_context`; the mixed Asset+Contract Candidate likewise is not a pure-declaration Candidate and must be counted as full context. Report those full-context rows separately from reducer reads, which run once before the writer and again inside the writer. Do not attribute context materialization to FactReducer or claim the reducer measurement alone represents total publication cost.

## Frozen interpretation and differential acceptance

D0 accepts as a measurement package only if it can reproduce every declared cell, preserves first failures, verifies H closure, shows actual P/A/depth, records row-return and VM/profile proxies with correct labels, and binds all evidence to exact code/script hashes. It must not assert a target complexity as a test expectation or fail merely because the baseline exposes a cost; the observed slope and failure are the output.

Freeze the downstream D decision rule before any optimization: for fixed P and fixed explicit references/A, compare H=0/16/64 separately for context, pre-commit reducer, and writer reducer. Report both total rows and unrelated-H rows. The target for the later D behavior package is that normal publication no longer materializes or iterates unrelated closed-H facts; indexed lookup VM may increase with index depth and must be reported independently. Necessary proof/closure work is charged to measured references, fanout, actual descendants and depth, not mislabeled as global H. P growth is reported independently, with batch and sequential publication distinguished so H locality cannot hide cumulative P cost. Numeric ratio thresholds for D's SQL VM and wall time remain unfrozen until D's audited implementation plan defines them from this baseline, before implementation begins.

Correctness setup must also use signed owners: cancel a real declared intermediate with `contract.cancel` after its descendants are declared, rather than append a terminal fixture; qualify an exact claim-bound producer output with a distinct registered actor’s signed attestation. Prefix setup is outside measured publication and its exact same snapshot is used by both twins.

For every correctness microcase and every paired matrix execution, compare the accepted bit, exact accepted Asset/Contract IDs, derived trace/runtime semantic digest, terminal/cancel outcomes, and read-only rebuild/materialization digest. Within each timing/twin pair, use identical signed input bytes and compare the semantic facts; the batch and sequential modes may use different Candidate IDs. Canonicalization omits only the display-time fields described above; it retains effect types, semantic payload, causal references and stable IDs. Preserve the existing writer-lock concurrent-output test as a separate correctness check in D's implementation package; D0 does not replace or weaken it. For same-batch, duplicate-name, activation, business-output and independent-qualification behavior, the benchmark smoke checks facts/decisions, not only metric shapes. No benchmark may equate task activation with claim eligibility or output assertion with independent acceptance.
