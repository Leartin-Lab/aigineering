# Execution permission and exact output eligibility

Status: Implemented development increment; stable qualification remains separate.

Tool scope is a permission ceiling, not a required checklist. Recovery Workers
may produce their declared business outputs without dispatching a tool merely
because tools are allowed. Sequential and parallel continuations retain the
parent-authorized tools, allowing another ordinary funded call to the same tool
with different arguments. Neither a continuation nor a planning child can widen
that scope. Both planning formats default omitted child allowance to one; actual
tool dispatch still requires funding for its tool task and continuation.

Historical continuation recognition retains exact previously committed input,
stage-label and consumed-scope constructions. It does not rewrite old Contracts,
refresh their context, manufacture a new publication or accept conflicting
history. Tool descriptor/schema checks, capability routing, signed submission,
claim fences, causal allowance and observation/business-output separation remain.

Independent acceptance can qualify an exact claim-bound output from another
Contract tree. Attestation, review request/decision and shared output selection
use the existing exact Asset/slot/policy relation rather than an additional
producer-tree restriction. Producer-declared output, submitted-claim publication
proof, distinct verifier, frozen context, shape and one-selected-Asset writer
checks remain. Review reports retain their requested reviewer provenance.
Business recovery with explicit `contract_tree` policy can use delegated
output. Historical recovery without that constraint retains its own-producer
rule to exclude stale repair inputs; system and protected recovery method
outputs also keep their mechanical own-producer rule.

Recovery publication no longer counts `.recover` substrings in a display name.
Causal funding and existing signed publication checks still limit publication.
Method recovery retains its exact source-history checks and proof-depth limit; this change does not remove all limits
on deep recovery chains.

No new table, fact type, scheduler, cache or authority is introduced. Existing
frozen policies and terminal facts are not rewritten; schema22 remains the reader
floor. The current mechanical `contract_tree` default is retained pending an
exact fulfillment relation: removing it alone would restore same-name false
completion. Generic short references and report slice citations are outside this
change.

Verification covers optional scoped output, underfunded actual dispatch,
sequential and parallel calls to the same tool, exact historical variants,
cross-tree independent qualification, stale recovery exclusion and reopen/rebuild.
Installed-wheel checks exercise changed behavior and standard CLI workflows.
This is deterministic evidence, not live-provider or large-history qualification.
