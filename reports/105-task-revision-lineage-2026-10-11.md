# Accepted revision publication lineage

Development evidence for an uncommitted `0.5.13.dev0` working-tree snapshot.
Machine-readable hashes and scope are recorded in
[data/105-task-revision-lineage-verification.json](data/105-task-revision-lineage-verification.json).

`task lineage ID` navigates the exact accepted publication connecting a
review-linked revision source and its successor. Both endpoints expose the same
verified component with independently derived task states. The ordinary review
child remains in that component through its proved containment edge. Handoff
and revision reuse a pure successor-publication proof; generic receipt/head/member
validation remains with the publication-history owner.

This proves accepted publication ancestry, rather than independently re-auditing
the historical review, evidence, allowance or assignment decision. It does not
decide current claim eligibility. Signing, publishers, claim writers, acceptance
policy and schema are unchanged. Invalid or competing relations do not expand
the component. Passive continuation, other recovery relations, folding and
natural scale remain separate work.

## Deterministic verification

Independent Luna review passed 186 focused tests after a prior review identified
two coverage gaps. Additional tests cover duplicate materialized task IDs and
revision endpoint/declaration mismatch. The mismatch tests prove valid generic
publication membership and isolate composition with a substituted canonical
status projection; they are not histories admitted through an ordinary writer.

The first integrated full suite had 2256 passing tests, 346 failures and six
setup errors. Connections to required local Redis were refused; its previously
observed process/listener were absent and no shutdown cause was recorded. The
stopped persistence files were backed up and byte-verified before recovery with
the same binary, data and persistence settings. A separate full run passed
2608 tests with six dependency warnings. Both failed and passing diagnostics
remain bound to unchanged source/public Markdown bytes.

Ruff, format, build and Twine passed. An external, noneditable wheel installation
matched all 229 source/wheel/sdist/installed modules. Its third-party packages
were shared with the development environment, so clean dependency-index
installation remains untested. Final document packaging is a separate binding
from the artifact actually used for installed execution; its governance, direct
reference, build and archive checks are recorded in the final closure evidence.

but remained submitted pending frozen independent acceptance. One ordinary
review child produced its own report. The default decision identity was refused
because it lacked the source policy's `policy.review` capability. An explicitly
authorized fixture identity then used the existing signed authorization owner
with exactly `asset.attest`, `policy.review` and `task.review.decide`; the source
policy, evidence and existing identities were preserved.

The subsequent changes decision and bounded revision committed through ordinary
owners. The source became cancelled, the reviewer child stayed completed, and
the new successor was ready. The original submitted claim was preserved; no
source or reviewer invocation was repeated. Exact revision replay preserved the
complete accepted result and runtime-record inventory. Both endpoint JSON and
human lineage, all three full CLI integrity cards, required Redis outage and
read-only reopen passed against the installed package.

The main installed attempt stopped at a private-copy checker defect: it omitted
the reviewer identity and indexed two selected endpoint views as if a third view
existed. The accepted decision/revision and its failure diagnostics are retained.
A separately reviewed six-phase read-only continuation rebuilt a new private
copy and matched both complete endpoint lineages, all three task and integrity
cards, record inventory and semantic digest. Its before/after full-value capture
proved the original 111 records unchanged. The original 89 complete record
values also remained an unchanged prefix after the accepted mutations. The main
failed result remains failed; the independent evidence review distinguishes its
22 new records and Redis use from the continuation's zero original writes or
Redis operations. Both added zero Worker or provider invocations.

the corrected invocation and failure were retained separately. These failures did not establish runtime defects; the
policy-capability refusal was an intended authorization fence. Failure scopes
and accepted partial results are retained rather than rerunning whole fixtures.

The two retained Worker invocations used explicit mocks. This slice adds no real
