## Implemented behavior

The quick-goal CLI accepts explicit UTF-8 file inputs and saves an authorized
text output as Markdown. It does not discover files, retrieve source material,
or load operator tools implicitly. Target-task runs are scoped to the requested
Contract and immutable descendants, expose projected blockers and a stop reason,
and leave a root recovery successor as explicit follow-up work. CLI numeric
timeouts must be finite and positive.

The canonical prompt now directs Workers to encode output strings with standard
JSON escaping; literal line breaks are not valid inside a JSON string. The JSON
parser remains strict; no permissive repair is used, and reasoning text is not
treated as output. Markdown examples are limited to ordinary
single-output Contracts without planner/control labels or output-shape policy.
OpenAI-compatible responses marked truncated or containing empty content have
stable failure codes, with validated provider usage retained through the
existing durable failure path.

The CLI now offers opt-in `--response-format json_object` for provider JSON
wire mode; omission preserves provider defaults. This is separate from
`--json`, which selects CLI output, and it cannot be combined with
`--tool-registry`. The adapter compiles the complete JSON response through the
canonical action wrapper and retains strict parsing. A later real quick-goal
run using this mode completed, but primary-agent review found that the generated
report's `task status` and `task audit` commands omitted their required
`CONTRACT_ID` argument. This is a model-content defect. The output was not
independently semantically accepted, and the successful task status does not
establish that its instructions are complete or correct.

Committed output remains an authorized assertion under its Contract.
Independent acceptance is a separate policy-bound step; neither commitment nor
an audit record proves semantic truth. The successful recovery below had no
independent attestation.
